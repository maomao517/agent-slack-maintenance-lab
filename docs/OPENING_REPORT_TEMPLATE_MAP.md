# 开题报告模板结构与材料准备映射

## 模板基本信息

模板：华中科技大学《硕士生论文开题报告》

版式要求：

```text
纸张：A4
页边距：上/下 2.54 cm，左/右 3.17 cm
一级标题：黑体、四号，自动编号 1--7
二级标题：黑体、小四，自动编号 2.1、2.2 等
正文：中文宋体、英文 Times New Roman、小四
正文行距：1.5 倍
正文对齐：两端对齐
页码：页脚右侧
```

封面需要填写：题目、学号、姓名、专业、指导教师、院系。末页需要研究生、指导教师和院系领导签字及日期。

模板渲染时封面后出现一页空白。初步判断是封面内容自然占满第一页后又插入了手工分页符。正式填充时应在 Word 中复核并删除多余空页，但不要修改原始模板，只在副本中处理。

## 当前选题工作假设

现阶段不要把题目写死为具体系统名。可以暂用：

> 面向多模态 Agent 工作流的跨轮推理状态管理与缓存优化研究

研究对象暂定为多轮多模态 Agent 在模型调用与工具等待之间产生的可复用推理状态，包括完整 KV Cache 和视觉 Encoder 状态。研究重点不是模型训练，而是在有限 GPU 显存和并发压力下进行状态 admission、保留、降级与淘汰。

正式题目需要等待真实 Qwen3-VL profile 后决定：如果 Encoder/KV 分级收益成立，题目可突出“分级状态租约”；如果 Encoder-LRU 更强，应改为“成本感知状态缓存”；如果没有稳定复用，则停止该方向。

## 按章节准备材料

### 1 课题背景、目的和意义

当前可写：

- Agent 工作流由多轮模型调用、工具执行和环境交互组成，中间存在长短不一的等待阶段。
- 多模态输入除文本 token 外，还包含视觉编码结果及其在 LLM 中形成的 KV 状态，重算与保留具有不同成本。
- 固定保留完整 KV 会占用大量显存，全部淘汰又会造成重复视觉编码和 prefill。
- 研究目标是提高有限显存下的跨轮状态复用效率，降低工作流 JCT、P95 延迟和重复计算。
- 该问题不依赖模型训练，适合实验室只做推理的条件。

已有材料：SGLang、Continuum、HERMES、CachedAttention、Prompt Cache、LMCache 等论文；本机合成参数扫描。

仍需补充：

- 一个明确应用场景，建议使用“多轮文档图像分析 Agent”，暂不扩展到长视频和 GUI Agent。
- Qwen3-VL 的 Encoder 时间、prefill 时间、Encoder 状态大小、KV 大小和跨轮复用率。
- 至少一张展示真实工具等待分布和重复计算占比的 motivation 图。

### 2 国内外研究现状

建议不要简单按国家罗列论文，而是按技术演进组织，并在每条主线中说明国内外代表团队：

#### 2.1 LLM/VLM 推理缓存与前缀复用

研究对象：PagedAttention、RadixAttention、Prompt Cache、CachedAttention、LMCache、Pensieve、Continuum。

写作落点：现有工作主要管理文本/KV 状态，证明前缀复用和跨请求状态保留能够降低 TTFT，但通常假设单一状态形态或固定生命周期。

#### 2.2 多模态状态压缩与分层管理

研究对象：SGLang 的图像 hash/KV 复用、HERMES 的分层视频 KV、VStream、VisRAG、ColPali/Light-ColPali。

写作落点：多模态系统已经研究视觉 token/KV 压缩和层级存储，但多数面向连续视频或检索索引，尚未充分覆盖工具驱动 Agent 的跨轮暂停、恢复和并发竞争。

#### 2.3 Agent 工作流调度与状态管理

研究对象：ContextPilot、AgenticCache、Agent Workflow Memory、SGLang structured programs、Continuum。

写作落点：Agent 系统开始利用工作流结构优化上下文、缓存和调度，但对 KV 与视觉 Encoder 状态的联合 admission、降级和公平性处理仍不充分。

#### 2.4 当前研究存在的问题

当前实验支持写入的问题：

1. 固定 KV TTL 无法同时适应短工具调用和长尾暂停。
2. 单一 Encoder-LRU 是强基线，简单增加两级缓存并不必然降低端到端延迟。
3. 依赖准确等待时间预测的策略在低估长尾时会选择错误状态层级。
4. 当前 Joint-Lease 在高并发合成场景下出现明显退化，说明 admission、降级和调度不能分开设计。
5. 现有合成结果还不能证明真实 VLM 中 Encoder 状态足够小、重算成本足够高。

这一节必须以论文证据和真实 profile 收束，不能只写概念判断。

### 3 研究目标与研究内容

#### 3.1 研究目标

暂定总体目标：

> 面向工具驱动的多模态 Agent 工作流，刻画跨轮视觉 Encoder/KV 状态的复用特征，设计在有限 GPU 显存下兼顾重算成本、等待长尾和并发公平性的状态管理机制，并通过真实 VLM trace 验证其对 JCT 和资源效率的影响。

#### 3.2 研究内容

可以拆为四项：

1. 多模态 Agent 工作流与推理状态 profile。
2. KV/Encoder 状态成本模型和统一描述。
3. admission、租约、降级与淘汰策略。
4. 原型实现及与强基线的实验评估。

最终是否保留第 3 项中的“两级租约”措辞，应由真实 profile 决定。

### 4 研究方案与可行性分析

#### 4.1 研究方案

当前已经可以写出方法链条：

```text
受控多模态 Agent workload
  -> 采集真实模型/工具 trace
  -> 分解 Encoder、prefill、KV、等待成本
  -> 回放 NoCache / Encoder-LRU / Fixed-KV-Lease / Joint-Lease / Oracle
  -> 判断收益条件和失败区域
  -> 实现最小状态管理原型
  -> 单卡与并发实验
```

实验指标：平均/P95 JCT、重复计算时间、KV/Encoder hit、forced eviction、峰值状态容量和 memory-time。

#### 4.2 可行性分析

当前已有证据：

- 不需要训练模型，使用已发布 checkpoint 做推理。
- 公司机器已有 8×V100 32GB，第一阶段只需一张卡。
- 已有 Qwen3-VL-8B-Instruct safetensors，可作为真实 profile 模型。
- 已实现五个策略的离散事件模拟器和 78 场景参数扫描，17 项测试通过。
- 已有系统性论文普查和多个开源系统/代码仓库可作为 baseline 依据。

风险及回退：

- Qwen3-VL 与当前 Transformers 不兼容：离线准备匹配 wheel，或更换已支持的轻量 VLM。
- Encoder 状态不具备大小优势：转向成本感知 Encoder 缓存或停止分级路线。
- Joint-Lease 高并发退化：将研究问题收窄到并发 admission 与公平性。
- 真实跨轮复用不足：停止缓存选题，回到 Agent 工作流调度或索引新鲜度方向。

### 5 进度安排

现在可以先准备阶段名称，具体月份需根据学校答辩时间补齐：


### 6 预期成果

可暂定为：

- 一套可复现的多模态 Agent 推理状态 trace/profile 方法。
- 一个无需模型训练的状态管理原型。
- 对五类策略在容量、等待长尾和并发条件下的系统性评估。
- 明确的适用条件、失败案例和回退机制。
- 完成硕士论文；是否承诺论文/专利应与导师确认后填写。

关键技术指标不能现在虚构。待真实实验后，再用 JCT、P95、重算成本和显存效率填写。

### 7 主要参考文献

当前论文普查已经足以建立参考文献池。开题初稿建议先选 25--35 篇核心文献，覆盖：

```text
Agent workflow / serving
KV 与 prefix cache
多模态 KV/视觉状态管理
Agent memory 与多模态 workload
基础系统与 baseline
```

模板要求参考文献最多列 6 位作者，超过 6 位加“等”或“et al”；会议论文需写会议名称、城市、国家、时间和页码；文献末尾不加标点。最终不能直接粘贴 BibTeX，需要统一转换为模板格式。

## 当前可立即准备的内容

优先级从高到低：

1. 完成 Qwen3-VL 单卡真实 profile，决定选题是否成立。
2. 从论文池选出与四条问题直接相关的 25--35 篇核心文献。
3. 写第 2 章的三级技术主线和第 2.4 节问题归纳。
4. 固定一个具体 workload：多轮文档图像分析 Agent。
5. 根据真实结果收敛题目、研究目标和创新点。
6. 再写第 1 章 motivation 和第 4 章完整方案。

现在最适合先写的是第 2 章研究现状骨架、第 4.2 节可行性，以及第 5--7 章的占位草稿。第 1、3、4.1 章可以准备结构，但应等待真实 profile 后再定稿。

# 阶段A至D实验结果问题与下一步方案

## 1. 文档目的

本文档记录公司环境中已经完成的真实多模态模型实验、当前结果能够支持的结论、尚不能支持的结论，以及进入缓存策略实验前必须补做的跨任务共享实验。

当前研究对象暂定为：**面向多模态智能体跨任务复用的分层视觉中间状态缓存系统**。

本文档不把尚未验证的跨任务收益写成既定事实，也不预设候选策略一定优于强基线。

|项目|当前记录|

|驱动|500.65.06|
|CUDA环境|12.1|

|Transformers|4.57.0.dev0|

## 3. 已完成结果

### 3.1 阶段A：真实性能校准

此前单图中等分辨率测量结果为：

|指标|结果|
|---|---:|
|视觉编码时间中位数|20,860.555ms|
|视觉编码时间P95|20,968.486ms|
|预填充时间估计中位数|126.691ms|
|视觉模块最大单个输出张量|2.4609MB|
|完整视觉可复用状态|30.375MB（当前medium验证页面实测）|
|KV cache大小|47.25MB|
|峰值GPU显存|16,972.6172MB|

阶段C已经进一步确认，完整可复用视觉状态由`image_embeds+deepstack`组成。当前medium验证页面按实际缓存张量统计为30.375MB。早期9.375MB来自另一组视觉序列长度估算，已经过期，不能用于当前容量分析。

### 3.2 阶段B：图像因素剖析

阶段B得到以下趋势：

1.视觉编码是端到端推理延迟的主要来源；
2.视觉编码时间随视觉token数近似线性增长；
3.完整视觉状态大小随视觉token数和图像数量增加；
4.KV cache大小随输入token规模稳定变化；
5.在页型固定、分辨率变化时，性能变化主要由视觉token规模解释；
6.在分辨率固定、页型变化时，不同页型的差异主要来自视觉token数，而不是页面语义类别本身。

这些结果支持将视觉token数、视觉状态大小和视觉编码时间作为缓存策略实验的核心工作负载参数。

### 3.3 阶段C：真实Encoder-Hit

已经实现了真正跳过视觉编码器的`Encoder-Hit`路径，并测试了三种存储位置：

```text
GPU
CPU内存
磁盘
```

当前medium验证页面的完整视觉状态统一按30.375MB计算。当前观察为：

|恢复路径|恢复时间|相对约18.9s视觉重算|
|---|---:|---:|
|GPU命中|接近0或低于当前测量分辨率|显著加速|
|CPU命中|约0.3s|约63倍加速|
|磁盘命中|约0.5s|约38倍加速|
|冷恢复|约18.9s|基准|

这里不能把三种后端统一表述为“63至65倍加速”。更准确的表述是：三种后端均显著快于视觉重算，GPU恢复开销接近测量下限，CPU恢复约0.3s，磁盘恢复约0.5s。

## 4. 目前结果已经证明什么

### 4.1 可以支持的结论

当前结果能够支持以下判断：

1.在当前模型和硬件配置下，重复视觉编码是明显的系统级延迟来源；
2.视觉中间状态可以被完整保存，并在后续推理中真实复用；
3.当前medium页面视觉状态为30.375MB，约为47.25MB KV cache的64.3%，仍小于完整KV cache，但容量开销不可忽略；
4.CPU内存和磁盘都可以作为视觉状态的后备存储层，传输或读取开销相对于18.9s重算时间较小；
5.文档版本变化可以导致缓存失效，版本一致性必须成为缓存键或有效性检查的一部分；
6.状态管理的研究重点应从单纯GPU内淘汰，扩展到跨任务共享和GPU、CPU、磁盘分层放置。

### 4.2 尚不能支持的结论

以下结论目前不能直接写进开题报告：

1.不能根据`Same-Image`轨迹证明真实Agent工作流普遍具有高跨任务复用率；
2.不能根据单工作流命中率证明不同任务共享缓存能够降低P95 JCT；
3.不能声称Shared Cache已经优于最强缓存基线；
4.不能声称分层策略在高并发环境下一定优于单层CPU缓存；
5.不能声称磁盘命中约0.5s代表真实物理磁盘冷读延迟，除非明确控制操作系统页缓存；
6.不能把峰值GPU显存16,972.6172MB当作缓存对象大小；
7.不能把最大单个视觉张量2.4609MB当作完整视觉状态大小；
8.不能在未核验V100的`bfloat16`执行路径前，将绝对延迟直接推广到其他GPU。

## 5. 当前实验存在的问题

### 5.1 跨任务复用证据缺失

阶段D目前验证的是单个工作流内部的页面重复访问：

```text
Same-Image
Page-Revisit
All-Distinct
Version-Change
```

它能够证明单工作流内部的复用机制和版本失效逻辑，但尚未回答核心系统问题：不同任务是否访问相同页面，以及共享缓存相对于每任务独立缓存是否减少总视觉编码次数和P95 JCT。

因此，当前最重要的缺口是**阶段D2：跨任务共享实验**。

### 5.2 命中率统计口径不够明确

目前已有命中率梯度`75%>58%~50%>42%`，但需要补充每个数值对应的轨迹、分母和命中层级。必须区分：

```text
单工作流视觉状态命中率
跨任务视觉状态命中率
GPU命中率
CPU命中率
磁盘命中率
编码避免率
```

建议每次访问记录`task_id`、`workflow_id`、`image_content_hash`、`document_version`、`cache_hit`、`hit_tier`和`encoder_called`。

### 5.3 容量竞争尚未被真实触发

在10%的安全缓存空间下可以容纳约665个中等分辨率页面状态，说明当前单卡、单任务、少量页面条件下，GPU内淘汰压力很弱。若只增加几个页面，无法证明复杂淘汰策略具有必要性。

后续应使用高分辨率、多图输入和大规模访问轨迹制造可解释的容量压力。大规模部分可以采用“真实模型参数+离散事件回放”，不需要真正执行数千次视觉编码。

### 5.4 `bfloat16`和软件栈需要核验

当前记录同时出现V100、`bfloat16`和`PyTorch2.9.1+cu128`。需要补充以下信息：

```python
import torch
print(torch.__version__)
print(torch.version.cuda)
print(torch.cuda.is_available())
print(torch.cuda.get_device_capability())
print(torch.cuda.is_bf16_supported())
```

还需要保存`nvidia-smi`输出。V100上的`bfloat16`可能不是后续架构GPU上的原生高效路径，因此建议增加FP16对照。该问题主要影响绝对性能解释，通常不影响同一环境内的相对缓存比较。

### 5.5 磁盘结果需要区分页缓存状态

磁盘命中约0.5s的结果需要注明是热文件缓存还是冷读。如果不能清理操作系统页缓存，应将结论限定为：

> 本地文件读取与反序列化路径约0.5s，显著低于视觉重算。

不能将其直接写成物理磁盘冷读延迟。

## 6. 阶段D2：跨任务共享实验

### 6.1 目标

验证不同任务访问同一文档页面时，Shared Cache能否相对于NoCache和Per-Task Cache减少视觉编码次数和P95 JCT，并分析并发缓存未命中导致的重复编码。

### 6.2 任务设计

固定同一张公开文档页面`P1`，构造不同文本任务：

```text
任务A：总结页面主要内容并给出证据区域。
任务B：提取页面中的表格字段并返回行列位置。
任务C：解释页面中的图表趋势并指出极值。
任务D：验证页面中的某个数值并给出计算依据。
```

任务提示词不同，但图像内容、模型版本和处理器配置相同。另准备至少3份不同来源的文档页面重复上述任务，避免结果依赖单页。

### 6.3 页面重叠率

设置四档页面重叠率：

|重叠率|构造方式|
|---:|---|
|0%|每个任务访问不同页面|
|25%|四个任务中只有一个共享页面|
|50%|约一半页面被多个任务共同访问|
|75%|大部分任务访问共同页面|
|100%|所有任务访问同一页面|

`0%`是负对照，`100%`用于展示共享收益上界，25%至75%用于观察收益随页面重叠的变化。

### 6.4 并发设置

并发工作流数量设置为1、2、4、8。每个条件预热5次，正式重复至少20次。若真实模型后端不能安全地并发运行，保持单卡顺序执行视觉编码，使用相同到达时间和恢复时间进行离散事件回放，并在结果中明确区分真实执行与回放。

### 6.5 缓存策略

至少比较：

```text
NoCache
Per-Task-Encoder-Cache
Shared-GPU-Encoder-Cache
Shared-CPU-Encoder-Cache
Shared-GPU-CPU-Tiered-Cache
```

缓存键至少包含：

```text
image_content_hash
document_version
model_revision
processor_config_hash
visual_input_config_hash
```

任务提示词不应默认纳入视觉状态缓存键，因为本实验要验证不同任务文本提示词之间共享同一视觉编码结果；但提示词相关的KV cache不能因此被错误共享。

### 6.6 请求合并对照

对Shared Cache增加两种实现：

```text
Shared Cache without request coalescing
Shared Cache with request coalescing
```

当多个任务同时访问未缓存页面时，请求合并只允许一个请求执行视觉编码，其余请求等待同一个进行中的结果。记录实际编码次数和等待时间，以识别缓存击穿问题。

### 6.7 主要指标

```text
total_encoder_calls
total_encoder_time_ms
cross_task_hits
cross_task_hit_rate
average_jct_ms
p95_jct_ms
gpu_peak_memory_mb
cpu_cache_size_mb
gpu_to_cpu_transfer_ms
cpu_to_gpu_transfer_ms
duplicate_encoder_calls
answer_consistency
version_invalidations
```

跨任务命中率定义为：

```text
cross_task_hit_rate
=来自其他task_id已经生成的视觉状态的命中次数
/所有跨任务可共享访问次数
```

编码避免率定义为：

```text
encoder_avoidance_rate
=被缓存跳过的视觉编码次数
/NoCache条件中本应执行的视觉编码次数
```

### 6.8 结果判定

阶段D2不预设Shared Cache必然有效。重点观察：

1.页面重叠率从0%增加到100%时，跨任务命中率和编码避免率是否同步增加；
2.Shared Cache相对于Per-Task Cache是否仍有额外收益；
3.并发增加后，无请求合并是否出现重复编码；
4.请求合并是否降低总视觉编码次数和P95 JCT；
5.CPU分层传输开销是否小于重新视觉编码的收益；
6.文档版本改变时是否只失效旧版本状态，而不错误复用。

建议把以下数值作为继续系统设计的工程参考门槛，而不是论文承诺：

```text
跨任务命中率具有随页面重叠率增加的单调趋势；
Shared Cache相对于NoCache显著减少视觉编码次数；
Shared Cache相对于Per-Task Cache在至少一个非100%重叠条件下仍有收益；
请求合并后并发重复编码次数接近1次/页面；
P95 JCT差异超过同条件重复测量波动。
```

## 7. 阶段E之前的候选研究方向

### 7.1 主方向：跨任务共享与分层视觉状态缓存

研究对象是`image_embeds+deepstack`构成的完整视觉中间状态，系统提供GPU、CPU内存和磁盘三级存储。核心问题是：在不同任务共享页面、并发访问和版本变化条件下，如何进行缓存键设计、请求合并、分层放置和失效管理。

### 7.2 备选方向：并发视觉编码请求合并

如果跨任务重叠率较高，但单卡容量竞争不明显，可以把研究重点收窄为并发缓存未命中时的视觉编码请求合并。它不依赖复杂的淘汰参数，问题边界清楚，实验也容易解释。

### 7.3 暂不作为主线：完整KV与视觉状态联合租约

当前结果显示，完整KV cache相对视觉状态的增量节省时间较小，而占用空间明显更大。因此，`Joint-Lease`保留为强对照和可能的扩展，不应继续作为开题报告的唯一核心贡献。

## 9. 当前阶段的开题表述

目前可以写入开题材料的谨慎表述是：

> 前期真实性能剖析表明，在当前模型和硬件配置下，视觉编码是多模态推理恢复过程中的主要延迟来源。当前medium验证页面的完整视觉中间状态实测为30.375MB，而重新执行视觉编码约需18.9s；将该状态保存在GPU、CPU内存或本地热文件后，恢复时间均显著低于重新编码。后续跨任务实验用于进一步验证页面重叠和并发条件下共享缓存与分层存储的系统收益。

这段话不会把尚未完成的阶段D2实验写成既定结论。

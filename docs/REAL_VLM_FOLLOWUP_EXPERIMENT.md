# 真实多模态模型后续实验方案

## 1. 实验目的

当前Qwen3-VL-8B-Instruct在V100 32GB上的单图测量结果为：视觉编码时间中位数20,860.555ms、预填充时间估计中位数126.691ms、视觉模块最大单个输出张量2.4609MB、KV cache大小47.25MB、峰值GPU显存16,972.6172MB。

这组结果提示视觉状态可能具有“重算成本高、状态体积小”的特点，但现阶段不能直接将其作为开题结论。后续实验应依次回答以下五个问题：

1. 20.86s是否确实是稳定的视觉编码时间，而不是首次初始化、图像预处理或计时误差？
2. 2.4609MB是否覆盖完整且可复用的视觉编码结果，而不是视觉模块返回的最大单个张量？
3. 缓存该状态后，能否真实跳过视觉编码，并保持后续输出正确？
4. 多轮文档图像分析任务中是否存在足够的同图复用，以及真实容量竞争？
5. 在相同容量、相同轨迹和相同并发下，简单的Encoder-LRU、中央处理器内存卸载和成本感知策略之间是否存在稳定差异？

只有前3个问题得到确认，才进入缓存策略实验；只有第4个问题成立，才有必要设计新的缓存管理机制。

## 2. 总体实验结构

|阶段|实验内容|是否需要真实模型|核心产出|
|---|---|---:|---|
|A|测量口径校准|是|可信的时间、状态大小和显存数据|
|B|图像因素性能剖析|是|分辨率、页型、图像数量与成本的关系|
|C|视觉状态真实复用验证|是|跳过视觉编码后的延迟与正确性|
|D|多轮智能体轨迹采集|是|复用距离、工具等待和并发轨迹|
|E|缓存策略回放与原型对比|回放不需要，原型需要|JCT、P95、重算成本和资源开销|

整个实验不训练模型。第一轮固定使用一张V100，模型、Transformers版本、CUDA版本、数据类型、注意力实现、提示词和解码参数均保持不变。

## 3. 图像集设计

### 3.1 图像选择原则

图像同时承担两种作用，二者不能混淆：

- **性能控制变量**：主要由处理后的分辨率、视觉token数、长宽比和单次输入图像数量决定；
- **应用代表性变量**：由正文、表格、图表、扫描件等页面类型决定，用于证明实验对应真实文档分析场景。

因此，不应只随机找若干图片，也不需要以自然照片为主。选图应满足：

1. 使用公开、无隐私、可在论文中说明来源的文档页面；
2. 页面文字和图形清晰，能够设计可核验的问题与答案；
3. 同一原始页面能够生成多个分辨率版本；
4. 同一类别至少包含3个不同来源的页面，避免结论依赖单页；
5. 保留原文件、来源地址、下载日期和裁剪或缩放记录；
6. 不使用公司内部文档，不把敏感提示词或模型输出带离公司环境。

派生图像统一保存为8位RGB PNG，移除透明通道、EXIF旋转信息、浏览器边框和无关桌面背景。PDF页面先按固定工具和固定参数渲染，再从同一份渲染结果生成不同分辨率版本；不要分别截图得到三档图像。

### 3.2 推荐页型

正式图像集建议使用12个原始页面，每类3页。

|编号|页型|页面要求|代表任务|
|---|---|---|---|
|T1-T3|正文密集页面|双栏或单栏论文、技术报告页面，包含标题和多个段落|主题概括、术语定位、证据引用|
|B1-B3|表格页面|财报、统计年鉴或公开基准中的完整表格，至少5行×4列|字段提取、行列比较、数值计算|
|C1-C3|图表页面|柱状图、折线图、组合图各一页，坐标和图例清晰|趋势判断、极值查找、跨图比较|
|M1-M3|混合或扫描页面|正文、图片、表格混排，或存在轻度扫描噪声和倾斜|版面理解、OCR、跨区域证据整合|

优先来源可选择：公开论文PDF、政府或国际组织公开报告、DocVQA样例、ChartQA样例、公开年度报告。若公司机器不能联网，应在可联网环境完成下载和来源登记，再按公司规定离线转移。

自然照片不是主实验对象。可以额外放入2张自然场景图片作为边界对照，但不应把它们与文档页混合后只报告一个平均值。

### 3.3 分辨率设置

对每个原始页面保持长宽比，生成以下三档版本：

|档位|目标总像素|近似示例|目的|
|---|---:|---|---|
|低分辨率|约0.25MP|512×512|观察低视觉token条件|
|中分辨率|约1.00MP|1024×1024|作为主要应用配置|
|高分辨率|约2.25MP|1536×1536|放大视觉计算和状态大小|

这里的尺寸是像素预算，不要求把非正方形页面拉伸为正方形。A4纵向页面应保持原长宽比，例如1MP版本约为841×1189。缩放后不得重新压缩到无法阅读文字。

必须同时记录模型处理器实际产生的`pixel_values`形状、`image_grid_thw`和视觉token数。原图宽高不能替代处理后的视觉输入规模，因为模型处理器可能再次缩放图像。

### 3.4 图像数量设置

从12个原始页面中选取同一份公开文档的连续4页，构造：

- 单图：1页；
- 双图：同一文档的2页；
- 四图：同一文档的4页。

多图条件下使用相同的总文本提示词结构，并记录每张图像对应的视觉token数。不要通过重复同一张图片伪装多页任务；重复同图只用于专门的去重对照实验。

### 3.5 图像清单

每张原始图像建立一条清单记录：

```text
image_id
category
source_title
source_url_or_dataset
source_page
download_date
license_or_public_status
original_width
original_height
derived_resolution
sha256
question_ids
```

建议目录结构：

```text
data/public_docs/
  manifest.csv
  originals/
  resized/low/
  resized/medium/
  resized/high/
  questions.jsonl
```

## 4. 阶段A：测量口径校准

### 4.1 固定环境信息

每次实验记录：

```text
GPU型号与显存
CUDA和驱动版本
PyTorch和Transformers版本
模型名称、版本和本地权重哈希
torch_dtype
attention implementation
视觉模块名称
处理器配置
```

实验期间固定`CUDA_VISIBLE_DEVICES=0`、批大小1和FP16，不与其他作业共享该GPU。运行前用`nvidia-smi`确认没有其他进程占用显存。

### 4.2 重复测量

先使用中分辨率正文页完成一次冒烟实验；成功后预热5次，正式重复20次：

```bash
CUDA_VISIBLE_DEVICES=0 envs/control/bin/python scripts/profile_local_vlm.py \
  --model-dir "$MODEL_DIR" \
  --image data/public_docs/resized/medium/T1.png \
  --warmup 5 \
  --repeats 20 \
  --output artifacts/traces/profile-calibration-T1-medium.jsonl
```

检查每条记录是否满足：

```text
forward_ms约等于encoder_ms加prefill_ms_estimate
预热后的encoder_ms没有持续下降趋势
同一条件的变异系数尽量小于5%
```

当前脚本使用CUDA事件测量视觉模块，并在完整前向前后执行同步，因此不会把CUDA异步执行直接遗漏；但仍需检查被hook的模块是否恰好执行一次，以及视觉编码时间中是否包含不希望计入的操作。

### 4.3 修正状态大小口径

当前脚本的`encoder_size_mb`是视觉模块返回结果中“最大单个张量”的大小，不是完整输出中所有可复用张量的总大小。后续脚本至少应同时输出：

```text
encoder_largest_tensor_mb
encoder_output_total_mb
encoder_output_tensor_count
每个输出张量的shape、dtype和大小
```

统计完整输出时应按张量对象去重，避免同一底层存储被重复计数。最终用于缓存容量的数值必须是“能够让后续语言模型跳过视觉模块所需的最小完整状态”，而不是峰值显存，也不是最大单个张量。

### 4.4 显存口径

至少区分：

- 模型加载完成后的静态显存；
- 输入张量进入GPU后的显存；
- 完整前向峰值显存；
- 单个KV cache状态大小；
- 单个完整视觉可复用状态大小；
- 为暂停工作流预留的缓存预算。

`peak_gpu_memory_mb`只能用于判断运行是否接近显存上限，不能直接作为缓存对象大小。

## 5. 阶段B：图像因素性能剖析

### 5.1 最小实验矩阵

为了在10天左右完成开题准备，先运行最小矩阵：

```text
4种页型×3个页面×3档分辨率=36个条件
每个条件预热5次、正式重复20次
```

如果单次仍约20s，该矩阵需要约5小时有效计算时间，适合无人值守顺序运行。第一天可先做12个中分辨率条件；只有结果稳定后再补低、高分辨率。

### 5.2 扩展矩阵

最小矩阵完成后，再对T1、B1、C1、M1运行1图、2图和4图条件。文本上下文另设短、中、长三档，例如约128、512和2048个文本token，用于区分视觉编码成本与预填充成本。

每个条件输出：

```text
encoder_ms的中位数、P95和标准差
prefill_ms_estimate的中位数、P95和标准差
forward_ms的中位数、P95和标准差
完整视觉状态大小
KV cache大小
视觉token数和文本token数
峰值GPU显存
```

### 5.3 要检验的关系

不预设内容类别会显著改变计算时间，重点检验：

1. 视觉编码时间是否随视觉token数近似单调增长；
2. 完整视觉状态大小是否随视觉token数和图像数量增长；
3. KV cache大小是否随视觉token数和文本token数增长；
4. 页型固定、分辨率变化时结果是否稳定；
5. 分辨率固定、页型变化时计算差异是否主要来自处理器生成的token数。

## 6. 阶段C：真实状态复用验证

### 6.1 正确性实验

必须实现两条真实执行路径：

```text
Cold：每轮执行图像预处理、视觉编码和语言模型预填充
Encoder-Hit：读取已缓存的完整视觉状态，跳过视觉编码，再执行语言模型预填充
```

在完全相同的输入、确定性解码参数和模型版本下比较：

- 语言模型接收到的视觉嵌入是否一致；
- 首个生成token的logits最大绝对误差；
- 贪心解码结果是否一致；
- Encoder-Hit路径是否确实没有调用视觉模块；
- 端到端恢复时间是否减少约一个视觉编码时间。

若无法真正跳过视觉模块，现有测量只能证明“可能存在可缓存状态”，不能证明缓存方案可实现。

### 6.2 存储位置实验

由于当前视觉状态仅测得2.4609MB，必须加入中央处理器内存卸载基线：

```text
GPU-Encoder-Cache：状态保留在GPU显存
CPU-Encoder-Cache：状态卸载到固定页内存，命中时传回GPU
Disk-Encoder-Cache：可选，仅作为较慢层级对照
```

分别测量保存时间、加载时间、主机到设备传输时间和恢复后的端到端时间。如果中央处理器内存加载只需数毫秒，而视觉重算需要20s，那么只研究GPU内淘汰可能缺少必要性，研究对象应调整为分层视觉状态存储或跨任务共享。

## 7. 阶段D：多轮智能体轨迹

### 7.1 四类轨迹

每个工作流固定4轮，构造以下可证伪轨迹：

|轨迹|图像访问序列|目的|
|---|---|---|
|Same-Image|P1→P1→P1→P1|视觉复用上界|
|Page-Revisit|P1→P2→P1→P1|模拟文档证据回查|
|All-Distinct|P1→P2→P3→P4|无复用负对照|
|Version-Change|P1-v1→P1-v1→P1-v2→P1-v2|验证版本失效|

每类轨迹至少使用3份不同文档，不能只用一个页面得出跨轮复用结论。

### 7.2 具体任务模板

以一份包含正文、表格和图表的公开报告为例：

```text
第1轮：识别第1页主题并给出证据区域。
第2轮：调用本地OCR或检索工具，定位与某指标相关的页面。
第3轮：重新引用第1页，与工具返回页面中的数值进行比较。
第4轮：调用本地计算工具，生成包含页码和数值依据的最终结论。
```

工具使用本地确定性程序，不需要联网。等待时间设置为250ms、1s、4s和长尾混合分布。固定等待实验用于解释机制，真实OCR、检索和计算耗时用于验证应用代表性。

### 7.3 并发设置

并发工作流数量依次设置为1、2、4、8。若Hugging Face后端不能安全地执行真实并发，可先采集单请求成本，再按相同到达轨迹做离散事件回放；报告中必须区分“真实执行结果”和“回放结果”。

容量不按任意数值设置，而按可供暂停状态使用的安全显存预算设置。先测量前台推理所需显存，再将剩余安全空间的10%、25%、50%作为缓存预算。额外报告能够容纳的真实对象数量，避免只写抽象百分比。

## 8. 阶段E：基线与候选策略

### 8.1 必须比较的基线

|策略|作用|
|---|---|
|NoCache|每次重算，给出延迟和计算成本下界基准|
|GPU-Encoder-LRU|最直接且当前最强的视觉状态基线|
|CPU-Encoder-LRU|检验小状态是否应直接卸载到中央处理器内存|
|Encoder-LFU|检验访问频率信息的价值|
|GreedyDual-Size-Frequency|经典成本、大小和频率感知缓存基线|
|Fixed-KV-TTL|固定TTL保留完整KV cache|
|Continuum-compatible KV|按Continuum公开机制管理工具等待期间KV cache|
|Joint-Lease|完整KV cache、视觉状态和释放态之间切换|
|Clairvoyant reference|使用未来访问构造离线参考，只作为上界或参考值|

如果现有模拟器中的离线策略不是严格数学最优，不应命名为Oracle，应称为`Clairvoyant reference`或“离线先知参考策略”。

### 8.2 候选策略

在真实性能支持后，候选策略可采用无需训练、无需大量调参的成本密度：

```text
value(i)=reuse_probability(i)×avoided_recompute_ms(i)/state_size_mb(i)
```

第一版不训练复用预测器。`reuse_probability`只使用可解释的工作流信息，例如同一文档是否仍处于活动任务、后续计划是否显式引用该页、状态最近是否命中。若无法稳定获得这些信息，则先比较不含预测项的`avoided_recompute_ms/state_size_mb`。

TTL改进可作为次要实验，而不是预先确定的创新点：用工具调用类型给出的预计完成时间设置到期时刻，并与固定TTL比较。若预计时间误差导致收益不稳定，则保留固定TTL作为工程选项，不把预测TTL写成核心贡献。

### 8.3 公平比较原则

所有策略必须使用：

- 相同输入图像、提示词和模型；
- 相同到达时间、工具等待和复用轨迹；
- 相同GPU缓存预算，以及单独报告的CPU内存预算；
- 相同正确性约束和版本失效规则；
- 相同预热次数和正式重复次数。

不能把一个策略的GPU与CPU总容量和另一个策略的纯GPU容量直接比较。

## 9. 指标与统计方法

### 9.1 主要指标

```text
平均任务完成时间（JCT）
P95 JCT
视觉编码重算次数和总时间
预填充重算次数和总时间
吞吐量
GPU和CPU缓存命中率
强制淘汰次数
峰值GPU显存
显存占用时长积
主机到设备传输时间
```

### 9.2 质量和安全指标

```text
贪心解码结果一致率
首token logits误差
证据页命中率
文档版本错误复用次数
缓存键冲突次数
```

每个主要条件至少重复20次，报告中位数、P95、均值、标准差和95%置信区间。策略差异必须大于重复测量波动；不能只展示最有利的一个容量点。

## 10. 决策门槛

### 10.1 继续视觉状态缓存方向

同时满足以下条件时，可以将选题收敛为“面向多模态智能体工作流的成本感知视觉中间状态缓存”：

1. 完整视觉状态能够被真实复用并跳过视觉编码；
2. 至少3份独立文档工作流存在跨轮同图或页面回访；
3. NoCache中的重复视觉编码使平均JCT或P95 JCT明显增加；
4. 在至少两个真实容量点上，LRU出现可解释的高成本对象误淘汰；
5. 候选策略相对最强非先知基线的收益超过测量噪声，并且不产生错误复用。

### 10.2 继续联合KV和视觉状态方向

只有当完整KV cache相对Encoder-Hit能够稳定节省不可忽略的时间，并且短工具等待场景足够常见时，才继续Joint-Lease。按当前单次结果，完整KV cache只额外节省约126.691ms却占用显著更多空间，因此这一路线目前证据较弱。

### 10.3 调整或停止

- 若CPU-Encoder-LRU已接近最佳结果：转向CPU/GPU分层视觉状态存储、跨任务共享或状态去重；
- 若所有视觉状态都能轻松保留：缓存淘汰问题不成立，转向版本一致性、跨任务去重或停止该方向；
- 若视觉输出无法独立复用：停止视觉状态缓存，改做KV cache管理；
- 若真实工作流几乎没有页面复用：停止该应用场景，不使用人工构造的高复用轨迹替代真实证据；
- 若20.86s在正确预热和计时后显著下降：使用修正后的数据重新判断，不保留旧结论。

## 11. 十天内的最小完成顺序

|时间|任务|完成标准|
|---|---|---|

# 视觉语言模型多轮状态缓存可行性实验报告（审校稿）

**实验时间**：2026年8月12日至2026年8月14日  
**实验模型**：Qwen3-VL-8B-Instruct（`Qwen3VLForConditionalGeneration`）  
**实验数据**：`public_docs`公开文档图像集，包括正文、表格、图表和混合页面4类页型，每类3页，并设置低、中、高3档分辨率

## 1. 实验目的

本实验用于验证多模态智能体工作流中视觉中间状态缓存的可行性，重点回答以下问题：

1.视觉编码是否构成多模态模型前向过程中的主要时延；
2.视觉编码时间和视觉状态大小如何随输入规模变化；
3.缓存视觉中间状态后，能否真正跳过视觉编码并保持推理结果一致；
4.将视觉状态保存在图形处理器（Graphics Processing Unit，GPU）、中央处理器（Central Processing Unit，CPU）内存或本地文件中，分别需要付出多大的恢复开销；
5.同一工作流内的页面复用和版本变化能否触发正确的缓存命中与失效。

阶段A至阶段D属于选题前置验证，不以证明某一复杂缓存策略最优为目标。实验结果主要用于判断研究对象是否可实现、性能问题是否存在以及后续研究边界是否清晰。

显存峰值统一使用`torch.cuda.max_memory_allocated()`记录，仅用于判断前向过程是否接近显存上限。缓存对象大小按照张量元素数量和数据类型字节数计算，不使用峰值显存代替缓存状态大小。

## 3. 阶段A：测量链路校准

早期实验曾采用“视觉编码时间约为完整前向时间的一半”的估算方式，并通过模块钩子记录部分视觉输出。该方法不足以支持正式结论。后续实验改为使用CUDA事件独立测量`get_image_features`的执行时间，并在前向前后执行设备同步，以区分视觉编码时间和语言模型预填充时间。

校准后的测量关系为：

```text
完整前向时间≈视觉编码时间+语言模型预填充时间
```

在中等分辨率条件下，视觉编码约为18s，语言模型预填充约为0.2s。校准结果表明，视觉编码占完整前向时间的主要部分，后续实验均采用CUDA事件实测结果，不再使用早期比例估算值。

## 4. 阶段B：图像输入因素性能剖析

### 4.1 分辨率对视觉编码的影响

|分辨率|图像高度|原始报告中的输入规模值|视觉编码时间中位数|`image_embeds`大小|峰值显存|
|---|---:|---:|---:|---:|---:|
|低|320px|491,520|4.82s|0.62MB|约16,900MB|
|中|640px|1,843,200|18.02s|2.34MB|约17,100MB|
|高|1,280px|7,618,560|74.88s|9.69MB|约21,300MB|

**口径提示**：原始报告将491,520、1,843,200和7,618,560标记为“视觉token数”，但这些数值需要与处理器输出的`image_grid_thw`和实际视觉序列长度重新核对。从数量级看，它们可能是处理后像素数或其他输入规模指标。完成核验前，正式开题报告不应直接将其称为视觉token数。

从当前规模指标看，图像高度增加一倍时，输入规模约增加至4倍，视觉编码时间增加约3.6至4.2倍。低分辨率到高分辨率的视觉编码时间由4.82s增长至74.88s，增幅约15.5倍。无论该规模字段最终对应像素数还是视觉token数，现有测量均表明视觉编码成本随视觉输入规模显著增加。

### 4.2 页型对性能的影响

|分辨率|不同页型的视觉编码时间中位数|页型中位数之间的变异系数|
|---|---:|---:|
|低|4.80至4.82s|0.14%|
|中|17.9至18.2s|0.12%|
|高|74.6至74.9s|0.08%|

这里的变异系数反映不同页型中位数之间的离散程度，不等同于同一条件20次重复测量的运行时变异系数。结果表明，在处理后输入规模相近时，正文、表格、图表和混合页面的视觉编码时间差异较小。计算成本主要由处理后的视觉输入规模决定，而不是由页面语义类别直接决定。

### 4.3 视觉编码与完整前向时间

|分辨率|视觉编码时间|完整前向时间|预填充时间估计|完整前向/视觉编码|
|---|---:|---:|---:|---:|
|低|4.82s|4.99s|0.17s|1.04|
|中|18.02s|18.23s|0.21s|1.01|
|高|74.88s|75.71s|0.85s|1.01|

视觉编码时间与完整前向时间接近，语言模型预填充时间约为0.17至0.85s。该结果说明，在当前单图预填充场景中，重复执行视觉编码是主要恢复成本，也是缓存视觉中间状态的直接动机。

### 4.4 图像数量扩展

|图像数量|文本token数|视觉编码时间|完整前向时间|峰值显存|
|---:|---:|---:|---:|---:|
|1|370|18.81s|19.56s|17,177MB|
|2|672|37.70s|约39s|17,364MB|
|4|1,276|74.53s|约77s|18,130MB|

图像数量由1增加至4时，视觉编码时间近似按图像数量线性增长。峰值显存只由约17.2GB增加至18.1GB，说明模型权重和前向计算占据了显存主体，而单个视觉输出张量的空间占比较小。

### 4.5 阶段B结论

阶段B可以支持以下结论：

1.视觉编码是当前模型前向过程中的主要时延来源；
2.视觉编码时间随视觉输入规模显著增加；
3.`image_embeds`大小随输入规模和图像数量增加；
4.固定输入规模后，不同文档页型的视觉编码时间差异较小；
5.输入分辨率和图像数量比页面语义类别更适合作为缓存工作负载的控制变量。

KV cache（Key-Value cache，键值缓存）大小约为94至288MB，但原始结果尚未给出各条件对应的完整表格。因此，正式报告中暂不写“KV cache随token数稳定”，应在补充输入token数、KV cache大小和重复测量方差后，再描述其变化规律。

## 5. 阶段C：视觉状态真实复用验证

### 5.1 正确性

实验通过替换`get_image_features`的执行路径，将缓存的视觉输出重新注入后续语言模型计算。命中路径没有再次调用视觉模块，说明实验实现了真正的`Encoder-Hit`，而不是对视觉编码时间进行离线扣减。

|检查项|结果|
|---|---|
|命中路径是否调用视觉编码器|否|
|首步logits最大绝对误差|0.000e+00|
|logits一致性|通过|
|贪心解码结果|一致|

该结果证明视觉中间状态能够被真实复用，并且在当前测试输入上没有造成模型输出差异。

### 5.2 缓存对象大小口径

原始报告给出两个不同口径：

```text
image_embeds：中等分辨率下约2.34MB
image_embeds+deepstack：此前记录约9.375MB
```

当前润色稿不能直接认定`deepstack`不属于完整可复用状态。需要通过一次消融实验确认：命中路径是否只恢复`image_embeds`，还是实际恢复了`get_image_features`返回的`image_embeds+deepstack`完整结构。

正式使用的`reusable_encoder_state_mb`必须等于“能够在不重新调用视觉模块的情况下保持logits一致所需的全部张量大小”。在该口径确认前：

- 2.34MB只能称为`image_embeds`核心张量大小；
- 9.375MB只能称为包含`deepstack`时的候选完整状态大小；
- 不能使用2.34MB计算最终缓存容量，除非消融实验已经证明`deepstack`可以安全省略。

### 5.3 分层存储性能

原始结果分别记录了缓存命中后的模型执行时间和状态加载时间：

|存储层级|冷恢复|缓存后模型执行|状态加载|估算端到端恢复|估算加速比|
|---|---:|---:|---:|---:|---:|
|GPU|18.65s|0.29s|0.00004s|约0.290s|约64.3倍|
|CPU内存|19.25s|0.29s|0.2353s|约0.525s|约36.6倍|
|本地热文件|17.98s|0.29s|0.2485s|约0.539s|约33.4倍|

上述端到端恢复时间采用“状态加载时间+缓存后模型执行时间”估算。不同阶段的中位数直接相加只能作为近似值，正式结果应由单一墙钟计时覆盖查找、加载、设备传输、状态注入和后续前向全过程。

原始报告中的“CPU和磁盘均获得63至65倍端到端加速”只使用了约0.29s的缓存后模型执行时间，没有计入CPU或文件加载时间，因此不能作为最终结论。当前数据更稳妥地支持：

> GPU、CPU内存和本地热文件命中均显著快于重新执行视觉编码；在计入已单独测得的加载时间后，估算加速比分别约为64.3倍、36.6倍和33.4倍。

CPU状态保存约需261.4ms，本地文件保存约需459.5ms。保存操作通常发生在首次计算后，不直接计入后续命中恢复时间，但会影响首次请求延迟或后台任务开销，后续应单独报告。

### 5.4 文件缓存口径

当前文件后端在同一实验循环中重复读取同一临时文件。首次读取后，文件可能进入操作系统页缓存。因此约248.5ms的加载时间表示本地热文件读取和反序列化路径，不代表物理磁盘冷读。

公司环境不宜为实验执行需要管理员权限的`drop_caches`操作。若不能在不影响系统的前提下获得冷读结果，应保留“本地热文件”这一限定，不必为了开题报告补做冷读实验。

### 5.5 阶段C结论

阶段C已经证明：

1.视觉状态缓存可以真实实现；
2.命中路径能够跳过视觉编码，并保持当前输入上的logits和贪心解码结果一致；
3.在当前环境中，GPU、CPU内存和本地热文件恢复均显著快于视觉重算；
4.视觉状态具备进一步研究跨轮复用和分层存储的可行性。

## 6. 阶段D：多轮工作流轨迹

### 6.1 理论缓存容量

|项目|当前测量|
|---|---:|
|完整前向峰值显存|16,901MB|
|设备可用显存|32,494MB|
|二者差值|15,593MB|

15,593MB是按一次前向峰值计算的理论剩余空间，不是已经扣除并发执行、CUDA内存池、碎片和安全余量后的“安全空间”。因此，按其10%、25%和50%计算的容量只能作为理论估算。

若单对象确认为2.34MB，则相应理论容量约为665、1,663和3,326个页面状态；若完整对象应包含约9.375MB的`deepstack`状态，则理论容量约为166、415和831个页面状态。正式报告必须在完整状态口径确认后选择其中一组，不能混用。

### 6.2 四类访问轨迹

原始报告给出以下结果：

|轨迹|访问序列|报告命中率|报告平均耗时|
|---|---|---:|---:|
|Same-Image|P1→P1→P1→P1|83%|13.8s|
|Page-Revisit|P1→P2→P1→P1|58%|32.3s|
|Version-Change|P1-v1→P1-v1→P1-v2→P1-v2|50%|43.4s|
|All-Distinct|P1→P2→P3→P4|33%|53.5s|

这组结果目前存在统计口径冲突。若每条4轮轨迹均从空缓存开始，并且不同工作流使用独立缓存，则理论命中率应为：

```text
Same-Image：3/4=75%
Page-Revisit：2/4=50%
Version-Change：2/4=50%
All-Distinct：0/4=0%
```

报告中的83%、58%、50%和33%说明实验可能包含预热访问、工作流间共享、额外轮次，或者命中率分母不是4次图像访问。这与“各轨迹使用独立缓存”的文字说明不一致。完成日志审计前，不能将该命中率梯度和“耗时降低74%”写入开题报告。

此外，“平均耗时”需要明确是每轮平均时延、每个工作流总任务完成时间（Job Completion Time，JCT），还是多次工作流运行的平均值。只有在四类轨迹采用相同定义、相同轮数、相同分辨率和相同重复次数时，才能直接计算降幅。

### 6.3 并发回放

并发结果来自离散事件回放，不是真实单卡并发执行：

|回放并发数|吞吐量|平均延迟|缓存命中率|
|---:|---:|---:|---:|
|1|0.11轮/s|8.93s|56%|
|2|0.21轮/s|8.93s|56%|
|4|0.38轮/s|8.93s|56%|
|8|0.66轮/s|8.93s|56%|

平均延迟和命中率保持不变，是当前回放模型的假设结果，不是实际系统在并发增加后仍保持稳定延迟的证据。该表可以用于说明后续实验方法，但不宜作为开题报告中的真实性能结果。

### 6.4 阶段D目前能够支持的结论

在命中率日志审计完成前，阶段D只能谨慎支持：

1.实验已经构造同页重复、页面回访、全不同页面和版本变化4类受控轨迹；
2.版本信息已经被纳入缓存失效测试；
3.现有缓存对象较小，当前12页数据集尚未触发真实容量竞争；
4.跨任务共享、真实并发、P95 JCT和复杂淘汰策略仍属于后续研究内容。

## 8. 当前可用于开题报告的结论表述

> 前置实验采用Qwen3-VL-8B-Instruct和单张Tesla V100-PCIE-32GB显卡，对公开文档图像进行了真实性能剖析。结果表明，在当前软硬件配置下，视觉编码构成单图前向过程的主要时延：中等分辨率页面的视觉编码约为18.02s，而语言模型预填充约为0.21s。进一步实验通过复用`get_image_features`的视觉输出真实跳过了视觉编码过程，命中路径与冷执行路径的首步logits保持一致。GPU、CPU内存和本地热文件中的视觉状态恢复均明显快于重新编码，说明视觉中间状态具备缓存和分层存储的可行性。后续研究将围绕完整视觉状态的统一表示、跨任务共享、版本一致性和分层放置展开，并在相同容量与相同工作流轨迹下与无缓存、任务内缓存和共享缓存等基线进行比较。

这段表述不使用尚未核验的阶段D命中率，也不把离散事件回放结果描述为真实并发性能。
